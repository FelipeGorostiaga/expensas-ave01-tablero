# Handoff: Expensas AVE 01 dashboard

Read this first. It tells a new Claude Code session, on a new computer, what the project is, how to clone it, and what it must never do.

## 1. What this is

A static dashboard that audits the monthly building expenses ("expensas") of **Fideicomiso AVE 01** (building "Alley", Buenos Aires). The administration (Administración Iriarte) sends one PDF liquidation per month, generated by the Octopus system. A Python parser reads the PDFs, a single `index.html` renders the analysis, and the data is published encrypted to GitHub Pages so the neighbours can open it with a shared password.

- Live site: https://felipegorostiaga.github.io/expensas-ave01-tablero/
- Repo: https://github.com/FelipeGorostiaga/expensas-ave01-tablero (public, GitHub Pages from `main`, root)
- UI language: Spanish. Code comments and commit messages: Spanish. This document: English.
- Owner: Felipe. He owns one unit in the building. The dashboard **must not** reveal which unit is his (it used to show "TH3"; that was removed on purpose). Keep it that way.

### Other operating systems and PDF folder

`refresh.sh` runs on macOS and on Windows (Git Bash). It finds the venv interpreter in `venv/bin` or `venv/Scripts`, and creates the venv itself if it is missing (`/usr/bin/python3`, else `uv`, else `python3`/`python`).

If the PDFs are not in the parent folder of the repo, write their folder (one line) in a local file `.pdf-dir` next to `refresh.sh`, or set `PDFS_DIR`. `.pdf-dir` is in `.gitignore`. On Windows use a Git Bash path such as `/c/Users/<user>/Desktop/expensas-data`.

The parser writes `data.json` and `data.js` with LF line endings on every system, so `data.enc` stays byte-identical across machines.

### Files that are NOT in git and must be copied by hand

## 4. How data flows

1. `parse_expensas.py <pdf_folder> data.json` parses every `*.pdf` in the folder with pdfplumber and validates each month against the printed totals. It also writes `data.js` (`window.EXPENSAS = {...}`) next to `data.json`. If `bank_statements.json` exists next to the script, it is merged into the payload.
2. `encrypt_data.py data.json data.enc .password` encrypts with PBKDF2-SHA256 (200 000 iterations) + AES-256-GCM. File format: salt(16) | iv(12) | ciphertext. Salt and iv are derived from the content, so unchanged data yields a byte-identical `data.enc` (no spurious commits).
3. `index.html` loads `data.js` when present (local preview) or fetches `data.enc`, shows the password gate, and decrypts in the browser with WebCrypto. The password is remembered in localStorage.
4. `refresh.sh` does steps 1 and 2, then commits `data.enc` (plus the source files) with message `Datos actualizados <date>` and pushes to `origin main`. It only works when the PDF list signature in `.pdf-state` changed; `FORCE=1 ./refresh.sh` forces it. A `mkdir` lock prevents concurrent runs. Log in `refresh.log`.

Manual regeneration:

```bash
FORCE=1 ./refresh.sh
```

Then check `refresh.log`: every month must say OK in the validation lines, and the last lines should read "publicado en GitHub" and "listo".

Local preview (never open `index.html` as `file://`, fetch of `data.enc` fails there):

```bash
python3 -m http.server 8765
```

Then open http://127.0.0.1:8765. With `data.js` present there is no password prompt. To test the gate, serve a copy of the folder without `data.js`.

### Automation on the original Mac (do not duplicate blindly)

On Felipe's Mac a launchd agent `com.felipegorostiaga.expensas-refresh` runs every 10 min (`StartInterval 600`) through a small AppleScript helper app (`~/Applications/Expensas Refresh.app`), because launchd cannot read `~/Documents` directly (macOS privacy). The helper must be re-signed (`codesign --force --sign -`) if its Info.plist is edited. Do **not** use launchd `WatchPaths` on the folder: it retriggers itself. There is also `../Actualizar tablero.command` for a double-click refresh.

If you set up the same automation on a second computer, two machines could push the same data. The deterministic `data.enc` makes this harmless, but keep only one machine automated to avoid push conflicts. On the second machine, run `FORCE=1 ./refresh.sh` by hand after `git pull`.

## 5. Payload shape (what `index.html` consumes)

`{ source_count, months: [...], bank_statements: [...] }`. Each month has: `period`, `due_date`, `grand_total`, `rubro_totals`, `items[]` (rubro, provider, cuit, date, description, expensas, abl, total, invoice, is_provision, is_reversal, installment, group, provider_inferred), `units[]` (uf, piso, owner, saldo_ant, pago, deuda, intereses, coef, expensas, extraordinarios, abl_avaluo, abl, gastos_part, cargos_part, redondeo, total), `unit_totals`, `financial` rows, `patrimonial` rows, `notes`, `juicios`, `provider_registry` (name, cuit, legal_name, address), `administration`, `validation`. No file names are in the payload (privacy).

`bank_statements.json` is a list of `{period, source, opening, closing, min_balance, deposits, sircreb, sircreb_rate, ley25413, fees, iibb_payments, notes}`. Add one entry per statement Felipe obtains, then `FORCE=1 ./refresh.sh`.

## 6. PDF quirks the parser already handles

Do not "fix" these; they are intentional.

- A rotated watermark in the left margin: characters with `x0 < 30` are dropped.
- Amounts are vertically centred within multi-line items: assigned by proximity.
- Unit table columns vary by month: Feb has an extra "ABL AVALUO" column, May lacks "Cargos Part.", Jun adds "GAST. PART.".
- Glued tokens such as `TH10PB` and `$0,001.4466`; CUIT and invoice split across lines; the typo "reintregro".
- Items can span page boundaries and are merged; statement rows split across pages are joined.
- Repeated unit labels (three new units "2SS" since Oct 2026) are suffixed "(2)", "(3)".

All 9 months validate against printed rubro totals, grand totals and the prorrateo totals row. Keep that invariant when touching the parser.

## 7. Dashboard structure (`index.html`, one file)

Redesigned in November 2026 (dark by default, Geist, six tabs). Still one file, no build step.

- Shell: header (unit picker pill and theme toggle), month selector (trend line on desktop, stepper under 720px), tabs, active section in `#view`, footer.
- Tabs and their question: Resumen (¿Qué pasó este mes?), Mi unidad (¿Cuánto pago yo?), Gastos (¿En qué se gasta?), Morosidad (¿Quién no paga?), Caja (¿Hay plata?), Revisar (¿Qué preguntar?). Hash deep links (`#gastos`); the old hashes (`#precios`, `#finanzas`, ...) map to the new tabs.
- State: `MI` (month index), `UF` (unit, empty by default), `TAB`, and `S` (per-section filters). `setMonth(i)`, `setUnit(uf)` and `go(tab, params)` re-render. Each tab registers a function in `TABS` that returns its nodes; `render()` rebuilds the shell and the active tab. Every month renders every block, including the first one (it has no previous month, and the comparison blocks say so).
- The analytics block (provider matrix, units, provisions, duplicates, jumps) is the same logic as before the redesign. `CONTROLS` and `QUESTIONS` feed Revisar, the tab badge and the Resumen alerts (`alertsAt(mi)`).
- `more(id, ...)` is a collapsible section. It keeps every full table of the old version reachable inside the new tabs; do not remove those without asking Felipe.
- Privacy: no unit is selected by default and none is named in the code. The design mockup files name Felipe's unit: never copy them into the repo.
- Password gate `#gate`: heading "Alley - Fideicomiso AVE 01", text "Los datos del tablero están encriptados.", show/hide toggle with a crossed eye at rest and a plain eye when toggled, no blue container on the icon.
- Charts are plain HTML/CSS (`colChart`, waterfall rows, bars) plus small SVG paths for lines and sparklines. Sortable `table()` helper. CSS tokens on `:root` (dark), overridden for light by `prefers-color-scheme` or by `data-theme` (the header button, stored in `expensas-tema`). Geist and Geist Mono. Rubro colours are fixed per rubro (`--c1` to `--c6`, `--cx`), never by rank.
- Keep `̀-ͯ` escaped in the accent-stripping regex; writing the literal characters broke it once. Keep `<meta charset="utf-8">`.
- Comparisons are month-over-month (plus "vs. 3 months ago" in the heroes), never against February. The one first-to-last comparison is "Cuánto subió cada uno" in Gastos, which replaced the old "Var. período" column. No footer with file names.

## 9. Findings so far (for continuity of the analysis)

- Security provider Cruz de Malta rose about 150 % between Feb and Sep 2026.
- Bank charges ("Gastos bancarios") multiplied in Sep and Oct. The Galicia statement for Oct 2026 shows they are SIRCREB withholdings of Ingresos Brutos at the 5 % maximum rate on every deposit (4.18 M in Oct) plus the impuesto al cheque (1.02 M). No IIBB payments to AGIP leave the expensas account.
- SIRCREB is a prepayment of the fideicomiso's own Ingresos Brutos (the fideicomiso is the taxpayer; the building is not yet "escriturado"). It is charged to the owners as a final expense. Accumulated owners-to-fideicomiso credit since it started: about 7.1 M (Sep estimated 2.9 M, Oct exact 4.18 M), roughly 4.5 M per month going forward. Felipe is raising this with the administration and the developer; the ask is that the fideicomiso recognises it as its own credit and returns it in the liquidation, and regularises its AGIP status to drop the 5 % rate.
- The printed "saldo de caja" is negative every month, but it is an accounting figure net of provisions. The real bank balance in Oct 2026 was +21.2 M with no overdraft. The page now shows the real balance and words the cash alert accordingly.
- Insurance (Zurich) disappeared Jul to Sep and returned in Oct as a new annual policy in 10 installments; not an irregularity.
- Unit B302 was unpaid for most months; total debt fell to 4.8 M in Oct after a 3.5 M payment.
- Oct 2026 added three units "2SS" and changed 22 coefficients with no note in the liquidation.
- Feb 2026 shows two 31 M "avalúo AGIP" installments paid outside the monthly ledger.
